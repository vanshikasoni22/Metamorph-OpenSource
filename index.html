Two modes, one evidence engine

Both modes run on the same pipeline, so every recommendation points back to something you can open and check.

Beginner mode

  1. 1

    Enter your GitHub username

    Contrib reads your public repos, languages and activity, then you set weekly hours, goals and learning pace.

  2. 2

    Pick an issue

    Three recommended issues, each with a personalized explanation of why it fits.

  3. 3

    Get your plan

    An implementation checklist, a learning plan and a suggested starting point.

After the PR: generate a feedback report on what went well and what to improve, based on the review and CI evidence available.

Maintainer mode

  1. 1

    Paste links

    Provide the issue URL and the PR URLs to evaluate.

  2. 2

    Analyze

    Collect repository evidence, inspect changes, run applicable checks and show progress.

  3. 3

    Review the results

    The top three PRs with scores, tags, supporting evidence and a concise explanation of each ranking.

Needs human review. Contrib advises and prioritizes. It never automatically merges or rejects a pull request.

What makes Contrib original

The differentiator is not which model we use. It is the system built around it.

01

Evidence collection

GitHub API · repository files · diffs · tests · reviews

02

Open-weight AI + embeddings

Interpret issues, understand code and match relevant information.

03

Contrib rule engine

Hard blockers · explicit scoring · evidence validation

04

Evidence-citing verdicts

Scores · reasons · file and line references · unknowns · human review

Unknown beats invented certainty. If a model says a PR implements a requirement, the validator checks that the cited evidence exists and supports the claim. If evidence is missing, the verdict says Unknown.

Measured, not assumed. Rankings are compared with human assessments on a small labeled set of issues and PRs, scoring ranking quality and evidence accuracy.
